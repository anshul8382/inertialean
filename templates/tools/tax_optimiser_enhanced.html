                Numeric gates include min_net_benefit_inr, min_tax_saved_to_trade_cost_ratio, turnover_sell_buy_multiplier, buyback_delay_days, etc.
            

            

                
Sort column — is it “priority”? Yes, in the everyday sense for this table: lower numbers appear first (10 before 20). The server returns rows in that order so you can read the playbook top-to-bottom.

                
Important: The engine runs book LTCG → book unrealised losses → book STCG (interactive queue order). The Sort column is for admin list order only. Defer / STCG sell hints are not strategies here — they attach to unified recommendation SELL rows.

            

            

                

                    

                        
                    

                    

                        

                            
S1 — Book LTCG within the annual exemption. Listed equity–style LTCG often has an annual exemption (e.g. ₹1.25L). This strategy looks at open lots that are already LTCG-eligible if sold and picks a small subset of sells (modelled as sell + buy-back) to use remaining headroom while minimising effective turnover.

                            
A concrete recommendation appears only when tax saved ≥ min_tax_saved_to_trade_cost_ratio × trade cost (default 2×) and min net benefit pass — no ratio bypass for missing marks.

                            
Params (common): min_net_benefit_inr, min_tax_saved_to_trade_cost_ratio (default 2), turnover_sell_buy_multiplier, buyback_delay_days, max_securities_per_client.

                        

                    

                

                

                    

                        
                    

                    

                        

                            
Low priority / conditional. The engine does not run this unless the client has open STCG unrealised losses or FY net realised STCG < 0. Then it applies marginal STCG tax / set-off gates (default require_fy_stcg_loss_offset).

                            
Params: same as before; deferral messaging for sells lives on unified recommendations, not here.

                        

                    

                

                

                    

                        
                    

                    

                        

                            
High priority — book unrealised losses (FY set-off). Only when there is realised gain this FY of the same character (STCG vs LTCG) on the report. Picks one open loss lot that clears the same 2× gates as LTCG booking.

                            
When prioritize_section_94_8_bonus_window is true (default), ties favour lots that are STCG unrealised losses on securities whose last bonus record date is roughly 9–12 months before the as-of date (§94(8) review context).

                            
Params: min_net_benefit_inr, min_tax_saved_to_trade_cost_ratio (default 2), turnover_sell_buy_multiplier, prioritize_section_94_8_bonus_window.

                        

                    

                

                

                    

                        
                    

                    

                        

                            
There is no separate “ranking overlay” strategy. The FY report shows a §94(8) priority badge and fills the §94(8) column (for matching securities) only when the client has an open STCG unrealised loss and the security’s last bonus record date (BONUS corporate action) is about 9–12 months before the as-of date.

                            
Harvest loss picking uses prioritize_section_94_8_bonus_window with the same window heuristic.
